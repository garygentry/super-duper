# Windows app components

This is the component view of the Windows app under `apps/windows/`. It maps the three projects and
their main parts so you can tell where a change belongs. For the processes around the app, see the
[system overview](overview.md); for how these parts behave at run time, see
[Windows app runtime scenarios](windows-app-runtime.md); for the rules a change must keep, see
[Windows app conventions](windows-app-concepts.md).

A rendered component diagram is pending; the tables below carry the same information.

## Projects and dependencies

| Project | Target | Packages | Holds |
|---|---|---|---|
| `SuperDuper.Windows.Core` | `net10.0` | CommunityToolkit.Mvvm | View models, navigation state, validation, worker and service contracts (`IWorkerClient`, `IUiDispatcher`, `IExplorerService`, ...) and protocol DTOs. No WPF, process or native references. |
| `SuperDuper.Windows.Infrastructure` | `net10.0-windows10.0.22000.0`, unsafe code allowed | Microsoft.Windows.CsWin32 | `WorkerClient` and the JSONL protocol, worker discovery and state locations, single-instance gate, Explorer, Cloud Files, Recycle Bin navigation, text scale, presentation preferences, the recycle executors |
| `SuperDuper.Windows` | `WinExe`, `net10.0-windows10.0.22000.0`, win-x64, `UseWPF` | Microsoft.Extensions.DependencyInjection | `App` (composition root), `MainWindow`, XAML views and their code-behind, WPF services (dialogs, clipboard, dispatcher), accessibility helpers, `ShellResources.xaml` |

Dependencies point one way: `SuperDuper.Windows` references both other projects,
`SuperDuper.Windows.Infrastructure` references Core, and Core references neither. Core defines the
interfaces; the other two implement them. Shared build settings (nullable, implicit usings,
deterministic builds, the product version) are in `apps/windows/Directory.Build.props`.

Native calls are generated by CsWin32 from
`apps/windows/src/SuperDuper.Windows.Infrastructure/NativeMethods.txt` (`SHParseDisplayName`,
`ILFindLastID`, `SHOpenFolderAndSelectItems`, `AllowSetForegroundWindow`). The dormant
`WindowsRecycleOperationExecutor` declares its Shell COM interfaces by hand. Cloud Files and
text-scale access use WinRT projections from the Windows target framework.

The app project copies `target/<debug|release>/super-duper-worker.exe` into its output after build
and publish, only when that file exists (`SuperDuper.Windows.csproj`, targets
`CopyWorkerExecutable` and `CopyWorkerExecutableToPublishDirectory`).

## Composition root

`apps/windows/src/SuperDuper.Windows/App.xaml.cs` builds the container in the `App` constructor,
after two steps that must happen first: in Debug builds only, applying a `.uidev` sidecar that
points at an isolated state folder, and resolving `WorkerStateLocations.FromEnvironment()` so the
single-instance gate can be keyed on the state folder. Every registration is a singleton, and the
provider is built with `validateScopes: true`.

| Service | Implementation | Notes |
|---|---|---|
| `IWorkerClient` | `WorkerClient` | Built with `WorkerExecutableLocator.Resolve()` and the resolved state locations. Also implements `IRestartableWorkerClient`, `IReviewLiveStateWorkerClient` and `IRecycleOperationWorkerClient`. |
| `IFolderPickerService` | `FolderPickerService` | WPF `OpenFolderDialog`. |
| `IUserConfirmationService` | `UserConfirmationService` | Yes/No/Cancel message box; No is the default and only Yes proceeds. |
| `IUiDispatcher` | `WpfUiDispatcher` | Runs inline on the UI thread, otherwise posts at `DataBind` priority. |
| `IClipboardService` | `WpfClipboardService` | |
| `IExplorerService` | `WindowsExplorerService` | |
| `IRecycleBinService` | `WindowsRecycleBinService` | Opens the Recycle Bin folder; never moves files. |
| `ICloudLocationService` | `WindowsCloudLocationService` | `UnavailableCloudLocationService` when `SUPER_DUPER_DISABLE_CLOUD_REGISTRATION_DISCOVERY=1`. |
| `IRecycleOperationCapabilityExecutor` | `DisabledRecycleOperationCapabilityExecutor` | Reports every item as not recyclable and throws on execution. See [ADR-0002](decisions/0002-review-only-windows-app.md). |
| `IPresentationPreferencesStore` | `JsonPresentationPreferencesStore` | Rooted at the state folder. |
| `ShellViewModel` | itself | Optional constructor parameters that are not registered (`TimeProvider`) fall back to their defaults. |
| `MainWindow` | itself | Has two public constructors; the container picks the one that also takes `IPresentationPreferencesStore`, because that service is registered. |

`ShellViewModel` constructs every screen view model itself and wires their callbacks, so the
container holds only the shell and services. View models discover the optional worker
capabilities (restart, live review state, the recycle ledger) by a type test on the injected
`IWorkerClient`, so a client without them still works.

## Shell and navigation

Navigation state lives in `apps/windows/src/SuperDuper.Windows.Core/ViewModels/ShellViewModel.cs`
and the enums in `WorkspaceDestination.cs`.

- **Areas and destinations.** Four `WorkspaceArea` values (Scan, Results, Review, History) group
  eight `WorkspaceDestination` values: ScanSetup, ScanProgress and ScanSummary; FileResults and
  FolderResults; Review; History and Performance. `SelectedArea` and `SelectedDestination` are two
  views of one state, and each area remembers its last destination.
- **Explicit view binding.** `MainWindow.xaml` declares a nested `TabControl` per area whose
  `SelectedValuePath="Tag"` is bound two-way to the area or destination. Each tab hosts a specific
  view with a fixed `DataContext` binding to a shell property. There are no implicit data templates
  or template selectors, so a view is found by reading `MainWindow.xaml`.
- **Lazy panes.** Files, Folders, Review and Performance load only when first shown for the opened
  run (`EnsurePaneAsync`), with one cached load per destination. Opening a different run cancels
  outstanding loads, clears the cache and resets those panes, so only one run's bounded state is
  retained.
- **Deferred departure.** Leaving Setup with unsaved edits is held until the user chooses Save,
  Discard or Stay in the overlay in `MainWindow.xaml`.
- **Shell chrome.** The saved-scans pane, the primary **Start scan** / **Scan again** button, the
  active-scan banner, the completion notice, the empty state, the error overlay and the connection
  recovery card are all bound to shell properties. `WorkerConnectionState` (Starting, Connected,
  Failed, RecoveryRequired) decides whether the workspace, the startup screen or the recovery card
  shows.
- **Focus requests.** View models raise a `FocusTarget` string plus a version counter; the
  code-behind in `MainWindow.xaml.cs` maps each target to a view's focus method.

## Worker boundary

The contract is `apps/windows/src/SuperDuper.Windows.Core/Workers/IWorkerClient.cs`; DTOs are in
`WorkerContracts.cs` and `WorkerProgressContract.cs`.

| Interface | Families |
|---|---|
| `IWorkerClient` | Lifecycle (`ConnectAsync`, `RunProgress` and `RunLifecycleChanged` events, executable and log paths); saved scans (list, get, create, update, delete); runs (list, get, start, cancel, warnings, exclusions, performance); duplicate files (groups, root and drive facets, members); review (plan, file and folder groups, decisions, live validation, dirty roots, reconciliation); whole-plan check (latest, get, start, items, cancel); location preference rules (list, get, save, preview, apply, applications, reverse); duplicate folders (groups, members) |
| `IRestartableWorkerClient` | `UnexpectedExit` event and `RestartAsync` |
| `IReviewLiveStateWorkerClient` | `ObserveReviewLiveState(run)` and the `ResultStateChanged` event |
| `IRecycleOperationWorkerClient` | Recycle-operation ledger and recovery-review methods; only the read and recovery-review methods are called from app code |

`apps/windows/src/SuperDuper.Windows.Infrastructure/WorkerClient.cs` is the only implementation.
It is responsible for:

- launching the worker hidden, with redirected strict UTF-8 streams, its own folder as working
  directory, and state paths passed as environment variables;
- the `hello` handshake (protocol 1 only, 10-second startup timeout) and mapping
  `database_unavailable` to `WorkerDatabaseUnavailableException`;
- serialized writes, integer request IDs and response correlation (`Protocol/ResponseCorrelator.cs`),
  framing and validation (`Protocol/JsonLineProtocol.cs`), and turning error responses into
  `WorkerProtocolException` with the worker's code;
- dispatching events: progress through the strict `WorkerRunProgressParser.cs`, run lifecycle, and
  `result.state_changed` filtered to the observed run; other events are ignored and the Review
  screen polls `preflight.get` instead;
- stderr capture: a 16 KiB tail for error messages and a timestamped copy in
  `BoundedDiagnosticLog.cs` (5 MiB, one `.previous` generation);
- exit monitoring, restart, and shutdown (stdin close, 2-second grace, then kill);
- watching completed runs' roots and batching hints (`ReviewLiveHintBatcher.cs`).

Worker discovery is `WorkerExecutableLocator.cs`: Release builds launch only the worker beside the
app; Debug builds honor `SUPER_DUPER_WORKER_PATH`, then the sibling worker, then the repository's
`target\debug` worker. State paths come from `WorkerStateLocations.cs`
([ADR-0005](decisions/0005-app-state-in-localappdata.md)).

## Windows services

All in `apps/windows/src/SuperDuper.Windows.Infrastructure/` unless noted.

| Component | Role |
|---|---|
| `WindowsExplorerService` | Reveals one item, or selects 1 to 200 items grouped by parent folder, off the UI thread; converts verbatim `\\?\` paths with `WindowsShellPath`. |
| `WindowsCloudLocationService` | Reads Cloud Files sync-root registrations off the UI thread and reports Complete, Unsupported or Unavailable. |
| `JsonPresentationPreferencesStore` | `presentation-preferences.json` in the state folder: at most 16 KiB, atomic replace, defaults on any load failure. |
| `WindowsRecycleBinService` | Opens `shell:RecycleBinFolder` in Explorer. |
| `WindowsTextScaleSource` | Windows text-size factor and its change event, consumed by `SuperDuper.Windows/Accessibility/WindowTextScale.cs`. |
| `SingleInstanceGate` | One app per state folder through a named event; a second launch asks the first window to come forward and exits. |
| `DisabledRecycleOperationCapabilityExecutor` | The production executor: nothing is recyclable and execution throws. |
| `WindowsRecycleOperationExecutor` | `IFileOperation` on a dedicated STA thread, at most 32 items per batch. Constructed only by tests. |

## Tests by layer

Test projects are in `apps/windows/tests/`. Run them serially (`-m:1`), as `AGENTS.md` requires.

| Project | Framework | Covers |
|---|---|---|
| `SuperDuper.Windows.Core.Tests` | MSTest 4, method-level parallel | View models, navigation, the progress gate, validation and formatting against in-memory doubles in `TestDoubles.cs`. No worker, no WPF. |
| `SuperDuper.Windows.Infrastructure.Tests` | MSTest 4, method-level parallel; worker-process classes are `[DoNotParallelize]` | JSONL protocol, progress parser, locator, state locations, preferences store, hint batcher, root watcher, single-instance gate, shell paths, Explorer, the disabled executor, diagnostic log. Real-worker lifecycle, `database_unavailable` and recovery tests report Inconclusive when the Cargo-built worker is missing. Opt-in categories `RealCloudProvider`, `RealRecycleBin` and `RealRecycleBinProvider` need environment variables; the Recycle Bin ones mutate the real Recycle Bin with disposable fixtures. |
| `SuperDuper.Windows.Smoke.Tests` | MSTest 3 with `Microsoft.NET.Test.Sdk`, tests run one at a time | Instantiates the real `App`, `MainWindow` and views on an STA thread with the Core test doubles linked in; checks theme, virtualization, AutomationIds, focus and shutdown ordering. No worker or interactive desktop. |

The real-desktop UI Automation journey against a running app and worker lives in
`scripts/Invoke-WindowsSmoke.ps1`, not in these projects.
